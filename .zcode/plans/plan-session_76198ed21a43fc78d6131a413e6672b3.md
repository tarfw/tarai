# TAR rebuild — tarfw.md end to end in tarharness + tarapp

**Starting point (verified by exploration):** the harness already has the right spine — D1 control plane + one Turso DB per workspace (src/db/turso.ts), commerce kernel laws in src/commerce/store.ts (balanced postings, `onhand−reserved` stock floor, version concurrency, idempotent fingerprints in gateway/commit.ts), and a site engine (src/site/, 11.5k LOC) that already does immutable R2 releases + rollback repoint, served by the sites/ worker. Google OIDC auth exists (auth/google.ts). Everything else is v4/v5-era and gets replaced: 12-table workspace schema, 18-tool registry, ~115 actions with verticals, Now/Space per-user inbox DBs, runtime Jev calls, a second POS stack, Slack/Discord team-chat, flows-as-surface. The app has no tab bar anymore but carries legacy surfaces (site studio, team admin, form onboarding, flow builder, routines, item editor) and a Turso device-replica layer that violates the tarfw device law.

**Assumption:** existing dev workspaces are disposable — old 12-table DBs are not migrated; birth re-creates workspaces under the 6-table schema.

All work on branch `rebuild/tarfw`. Commit per phase.

## TILE 1 — Harness foundation: truth schema + one TAR door
1. **Workspace schema v2** — rewrite `src/db/schema.ts` to exactly 6 tables per tarfw §Schema: `record(id,type,data,version,owner,created,archived)`, `move(id,kind,record,key,amount,why,source,created)` append-only, `current(kind,key,data)` derived, `skill(id,shape,trigger,steps,score,confirmed)`, `run(id,skill,step,status,key,input)` same-key-never-twice, `inbox(id,member,move,tool,reach,due,assigned,status)`; `events` becomes a VIEW over `move`.
2. **Write engine** `src/truth/write.ts`: one transaction = record + move + current + inbox (cost-guard law). Re-home kernel laws from `commerce/store.ts` (posting balance check, stock floor, version concurrency); idempotency = fingerprint on `move.key` (adapt `gateway/commit.ts`).
3. **Undo**: undo intent writes the opposite move + compensating record revision (owner money taps).
4. **Gates** `src/truth/gate.ts`: auto (inputs known, reach none/data) / ask (input missing) / approve (money/customer); code floor: auto+money → approve.
5. **TAR API** — rewrite `src/index.ts` routing: `POST /v1/auth/session` (Google OIDC → TAR session token, jose), `GET /v1/me` (workspaces + badge counts), `GET /v1/slice` (my inbox rows + my cards' numbers; ETag = last move id, if-none-match → 304), `POST /v1/intent` (action, input, idempotency key → queue → action → gate). Control actions for birth/join/archive: idempotent, one D1 workspace+owner row + fresh Turso DB + empty R2 layout; slug from name, collisions numbered; locale → currency/tax.
6. **14-tool registry** — new `src/tools/registry.ts`: per tool — id, card config (title, number read chosen by role, one tap, reach), sheet field configs, shape (list/sale/chat/sheet), nature recipes for birth card-dealing. Tools: pos, order, invoice, payment, register, catalog, stock, purchase, expense, contact, member, site, task, channel.
